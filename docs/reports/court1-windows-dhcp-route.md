# Court 1 Windows DHCP/route timeout — host correction

The 2026-11-19 attempt acknowledged one BLE maintenance proof, saw the exact AP, and established WPA2/CCMP at 19.869 s. The earlier one-shot wrapper then polled for a DHCP-origin address and the selected on-link route. It expired 23 s after its sole join request. It logged link state but not rejected addresses, selected routes or TCP reachability, so `dhcp_or_route_timeout` does not distinguish those conditions. Windows DHCP Admin events 50067 and 50065 for the Court 1 SSID record SSID receipt and a cache match, **not a lease**. The Operational channel was disabled. The disconnected interface had a deprecated link-local IPv4 address when inspected later; that is not evidence of its state during the attempt. The last positive installed witness already obtained DHCP and authenticated HTTP on the same firmware. Current firmware source checks `esp_netif_dhcps_start()` before enabling the AP; that is not packet-level proof of a DHCP response. No firmware change is supported by this evidence.

`tools/ota_windows.py` now checks the address and route independently. The old shared route helper assumed `Find-NetRoute` returned a source object before a route object, and did not check the route object's own interface index. A deterministic reversed-result regression fails with the old helper and passes with CIM-class selection. A foreign interface on either result fails closed. The old wrapper also called separate PowerShell processes without assigning the remaining join budget to them. The production CLI now gathers one snapshot per poll (capped to the time remaining); it will distinguish no preferred DHCP lease, APIPA, missing/non-direct route, wrong adapter/source, inspection failures and TCP unreachability. The 60-second combined budget reserves at most 30 seconds for fresh AP discovery (prior observation took up to 27 seconds); it permits at least 30 seconds after discovery for the one join and readiness checks. It does not extend firmware timers, change IP/metrics or replay association. TCP and HTTP both bind to the validated lease on the pinned interface.

Cleanup keeps the first error, attempts the authenticated close only when a session exists, restores WLAN and verifies Ethernet even if earlier cleanup failed. Close ACK, Windows link loss and BLE recovery are separate observations. No authenticated session was reached on the failed attempt, so closure and BLE recovery were not verified. The [verification-only live test](../agent-ota-deployment.md#court-1-one-verification-only-windows-networking-test) is prepared but not authorized or run. Its result is needed to establish actual readiness on Court 1; the cause of the previous on-air timeout cannot be reconstructed from the retained data. No device contact, firmware rebuild, upload or scoring change was made during this correction.

Local evidence: `20261119-pi-court1-portrait-order-live/` contains the failed attempt; `20261119-pi-windows-dhcp-route/` contains the red regression, full CLI suite, and read-only Windows cmdlet output from the disconnected host.
